| DL-0014 | 2026-07-17 | Technical Owner | M3.3 Endpoint Intelligence Framework decides turn completion via a configurable policy, but the completion **trigger** stays at the STT-final segment boundary; VAD signals **enrich** the decision, they never independently trigger a response | The prompt requires "replace the STT-final heuristic … completion must now be driven through the Endpoint framework" AND "the local profile should continue to function." So the pipeline feeds each segment to `EndpointEngine.note_segment`, and the *engine* (governed by `EndpointPolicy`) decides: the default policy confirms on-segment immediately (behaviour identical to pre-M3.3, no regression — verified end-to-end), while `silence_hold_frames`/`min_silence_frames` > 0 defer confirmation to VAD silence for a streaming profile. VAD `SPEAKING`/`SILENCE_CONFIRMED` feed the engine's speech/silence runs (enrichment) but the response trigger is the segment decision, avoiding desync with transcript availability. The endpoint framework is **always wired** (unlike the optional VAF). Both endpoint errors root in `RuntimeConflict` (lifecycle violation), consistent with the turn/VAD/conversation machines; the framework has no provider, so no `ProviderError` variant. `EndpointDecision` is a new completion concept — no conflict with `TurnPhase`/`TurnState`, no reconciliation debt. | [endpoint-framework spec](../docs/runtime/endpoint-framework.md), Constitution §A6/§A4.2 | Fully independent acoustic-silence-triggered completion in the live pipeline (no STT segment needed), semantic/smart-turn EOT, and adaptive delay are M3.4+ (additive: alternative engine or policy behind the same coordinator) | Accepted |
