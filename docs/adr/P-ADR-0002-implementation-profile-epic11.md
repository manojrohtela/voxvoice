## What this binds

Six profile changes, arising from the M11.0a decision gate.

### 1. Pipeline substrate — **retired**

**Pipecat ≥ 1.4 is no longer bound as the pipeline substrate.** VoxVoice retains its first-party
`RuntimePipeline`. Narrow, single-purpose third-party libraries may still be rented for genuinely
commodity work, confined to the layers already permitted to hold them: a **vendor SDK inside its
own Provider Plugin** (AR-12) and a resampling library inside the single resampler module
(ADR-0044 AD4).

**ADR-0002 is not amended and not contradicted.** Its Selected Solution reads *"The runtime **may**
use a third-party pipeline substrate"* — permissive, not mandatory. That permission is here
exercised **in the negative**. AR-13 (*"The Pipeline Substrate is imported only by
`runtime/pipeline/`"*) remains in force and is now satisfied vacuously; it is retained so that any
future substrate adoption is still constrained.

### 2. Real-time Transport — **first-party WebRTC Provider Plugin**

*"WebRTC via substrate's small-WebRTC transport"* is retired. Transport becomes a **first-party
WebRTC Provider Plugin** implementing the unchanged `core.providers.transport.TransportProvider`
contract, with its WebRTC library confined to that plugin under **AR-12**.

This also dissolves a pre-existing three-way conflict rather than working around it: the retired
row required `providers/transport/` to import the substrate, which **AR-13** forbids. With no
substrate, AR-11, AR-12 and AR-13 all hold simultaneously, and **no Constitution Part A amendment
is required**.

### 3. Vendor bindings — **accepted as they stand**

Unchanged from P-ADR-0001 and re-affirmed for Epic 11:

| Capability | Binding |
|---|---|
| Streaming STT | **Deepgram**; **Sarvam** for Hinglish |
| Streaming TTS | **Cartesia**; **Sarvam** (Hinglish) |
| LLM | **Groq** (low-latency); **Anthropic** (quality) |
| Storage | **Supabase** storage |

**No ungoverned vendor is introduced.** Any addition requires a further Profile ADR.

### 4. Prototype divergence — **not adopted**

`platform/voicebot/bot.py` uses **Groq Whisper** as STT. That prototype is excluded from packaging
and from the test suite and is **not** the governed integration path. **Deepgram remains the bound
streaming STT; Groq remains bound as an LLM only.** The prototype is retained for its vendor
wire-behaviour knowledge (AR-54), not as code to promote.

### 5. Dependency tooling — **`uv`**, with a committed lockfile

| Item | Binding |
|---|---|
| Tool | **`uv`** |
| Lockfile | committed; it is the **release artifact** |
| `pyproject.toml` | may keep version **ranges**; the lockfile pins resolved versions |
| Every dependency | a **DECISION_LOG** entry naming purpose, licence and blast radius (CODING_STANDARDS §7) |
| Licence | must be compatible with commercial use |
| Vulnerability audit | required in CI, failing on **high/critical** with a triage path (SECURITY_POLICY §6) |
| Vendor SDKs | one per plugin, imported only there (**AR-12**) |

`uv` is selected because it produces a cross-platform lockfile from the **existing**
`pyproject.toml` with no restructuring, and satisfies CODING_STANDARDS §7's *"one library per
job"*. It is a profile binding and therefore cheap to reverse.

**No dependency is added and no lockfile is generated by M11.1.** Generation happens at M11.2/M11.3.

### 6. Python version — the observed drift, resolved

Three sources disagreed today:

| Source | States |
|---|---|
| Constitution Part B | `Python 3.12, asyncio` |
| `platform/pyproject.toml` | `requires-python = ">=3.11"` |
| `platform/.venv` | Python **3.13** |

**Part B is the governing statement**, so the resolution is stated against it rather than against
the environment:

- **Floor: 3.12.** `pyproject.toml`'s `>=3.11` is **looser than the binding** and is tightened to
  `>=3.12` at M11.2. Until then, 3.11 is permitted by the packaging metadata but not by the
  profile.
- **Ceiling: none declared.** 3.13 is permitted; the venv is therefore compliant once the row says
  so.
- **The exact release interpreter is pinned by the `uv` lockfile and named by the CI matrix**, not
  by prose — which is what makes the number reproducible rather than asserted.

The Part B row is updated to state this. This is a **clarifying** change to a third row, made
because the M11.0a charter required the drift to be resolved explicitly rather than left to
guesswork; it changes no technology selection.

## Part B changes — exact

Three rows in `docs/architecture/engineering-constitution-v2.md` Part B:

| Row | Change |
|---|---|
| `Pipeline substrate (§A6.4)` | **Selection retired** — "Pipecat ≥ 1.4" → first-party `RuntimePipeline`; no substrate bound |
| `Real-time Transport plugins` | **Selection replaced** — "WebRTC via substrate's small-WebRTC transport" → first-party WebRTC Provider Plugin |
| `Backend language & concurrency` | **Clarified** — "Python 3.12" → floor 3.12, release interpreter pinned by lockfile + CI matrix |

One row **added**:

| Row | Content |
|---|---|
| `Dependency tooling & lockfile` | `uv`; committed lockfile is the release artifact; ranges in `pyproject`; DECISION_LOG entry + licence + blast-radius review per dependency; vulnerability audit in CI |

**No other Part B row changes.** In particular, `Deploy Stage 2 target` already reads *"One cloud
VM (current: Oracle A1 class) + systemd + managed Postgres | Any host with a public IP for media
relay"* and already binds the M11.0a **D-14** ruling, so it needs no change. `Language moat evals`
already places phrase sets under `evals/`.

## Why

Adopting Pipecat now would place a second frame pipeline, a second VAD and a second turn-taking
engine beneath the five turn-intelligence frameworks that **ADR-0001 names as the product**
(*"turn-taking, interruption, memory, timing, events, control"*), at the exact moment those
frameworks first run against real audio. ADR-0001 already rejected that shape as *"a framework to
wrap rather than a product to own."* It would also put a verified **5447-test** floor at risk for
no product gain, and the substrate is not currently installed — so nothing is lost by declining it.

What ADR-0002 correctly identified as commodity — transports and resampling — is rented anyway,
just at the narrow granularity the layer rules already sanction, rather than as a whole pipeline.

## Migration note

- Epic 11 **absorbs** the WebRTC and resampling work that ADR-0001's risk section expected the
  substrate to carry. This is a real cost and is recorded as a risk, not waved away.
- `runtime/pipeline/__init__.py` still states *"no substrate import yet; the substrate is wired in
  at M2."* That sentence is now false in a second way and is corrected at **M11.2**.
- **AR-13 is retained, not deleted.** Should a substrate ever be adopted, the confinement rule is
  already in force.
- The `uv` lockfile and the CI vulnerability audit are implemented in the **M11.2/M11.3** window,
  not here.
- Target-language (Hinglish) streaming remains **unverified**; P-ADR-0001's deferral stands, and
  ADR-0046 **FT-D8** provides the mechanism that will record the answer honestly.

## Change process for this profile

Unchanged from P-ADR-0001: profile changes require a Profile ADR plus the Part B table update in
the same change-set (DOCUMENTATION_RULES), reviewed per REVIEW_CHECKLIST. Part A remains protected
by constitutional ADRs. Accepted ADRs — including P-ADR-0001 — are **immutable**; this document
supersedes two of its rows rather than editing them.
