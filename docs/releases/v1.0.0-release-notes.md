# Epic 6 — Execution Platform v1.0 — Release Notes

**Version:** v1.0.0 · **Tag:** `v1.0.0`
**Date:** 2026-07-26
**Status:** ✅ Production Certified · 🔒 Epic 6 Frozen
**Builds on:** Runtime Platform v1.0 (Epic 5)

## Executive Summary

Execution Platform v1.0 is the first official production baseline of VoxVoice's
execution/agent layer. It elevates the Epic 5 Runtime Platform (a provider-neutral
reasoning stack) into a complete, autonomous, tool-using, multi-step agent
platform. Every capability was built design-first, independently certified, and
then frozen at M6.8F. This release is the immutable reference point that all future
development extends.

## Platform Overview

VoxVoice is composed in two frozen baselines:

- **Runtime Platform v1.0 (Epic 5)** — Memory, Knowledge, Context, Prompt,
  Reasoning, Provider, and the Runtime Pipeline.
- **Execution Platform v1.0 (Epic 6, this release)** — Tool, Skill, Hooks,
  Workflow, Agent, Loop, Platform Integration, and MCP, layered on Epic 5.

Each capability owns exactly one concern, depends only downward onto the shared
contract floor, and is wired together solely at a composition root.

## Major Capabilities

- **Provider Runtime** — the single execution boundary to external AI providers.
- **Tool Runtime** — executes external capabilities an agent invokes, with
  governance, policy, observability, replay, and streaming.
- **Skill Runtime** — reusable, versioned, declarative capabilities (manifest, not code).
- **Hook Framework** — deterministic cross-cutting lifecycle interception.
- **Workflow Runtime** — deterministic orchestration graphs over Skill/Tool/Hook.
- **Agent Runtime** — long-lived autonomous orchestration: goal decomposition, delegation.
- **Loop Engine** — deterministic propose→critique→repair→validate→stop-check.
- **Platform Integration** — the composition root wiring the platform end-to-end.
- **MCP Runtime** — client-side Model Context Protocol communication with external servers.

## Architectural Highlights

- **Single ownership** — one capability, one concern; none assumes another's role.
- **Acyclic, downward-only dependencies** — capabilities import only the contract
  floor; never a sibling, never a composition root.
- **Composition roots are the only integration points** — pure sinks; nothing
  imports them back.
- **Deterministic execution** — offline-default adapters; injected clocks.
- **Replay ownership** — capability-local, hash-chained, own-frames-only.
- **Observability ownership** — capability-local; cross-capability correlation by `trace_id`.
- **Tenant isolation** — no connection, credential, or replay shared across tenants.

## Extension Policy

Future Epics **extend** this baseline; they never modify it.

- **Allowed:** composition · adapters (implement a frozen port) · bridges (new
  composition-root module) · plugins (new manifests) · configuration · new
  capabilities (depend only on the contract floor, wired at a composition root).
- **Forbidden:** ownership changes · dependency inversions · runtime redesign ·
  breaking public contracts (additive, versioned evolution only).

## Known Limitations

- **Offline-certified providers/transports.** Certification is against
  deterministic offline adapters and first-party local servers; a real third-party
  vendor SDK / MCP-server interop path is validated only in an integration
  environment, not in this baseline.
- **Real wall-clock timeout/latency** behaviour is defined and enforced but not
  benchmarked against production networks.
- **ADR-0011 is absent** (documentation only) — reserved for the MCP↔Tool bridge;
  the code references the covering ADRs (0012 + 0015). No runtime impact.

## Version Compatibility

- **Execution Platform v1.0** requires **Runtime Platform v1.0** (Epic 5).
- SemVer at the baseline level: **MAJOR** = a breaking change to a frozen public
  contract (requires a new baseline + ADR); **MINOR** = additive
  capability/adapter/bridge/plugin/config; **PATCH** = hardening/bug-fix with no
  contract change. Epic 7 additions ship as **v1.x**.

## Next Roadmap (Epic 7)

Epic 7 builds on this frozen baseline via the sanctioned extension mechanisms —
new capabilities and composition-root bridges (e.g. multi-agent orchestration,
A2A, real vendor/MCP adapters, the developer platform/SDK/dashboard surfaces) —
without modifying any frozen Epic 6 runtime.
